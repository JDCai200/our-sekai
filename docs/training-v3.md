# 0.2 版模型扩展

本次将 MASTER 谱面语料由 300 首扩到 600 首，训练 427 首、验证 86 首、测试 87 首；八个起音组构成一个片段，总计 44,893 个合格片段，其中训练 32,030 个。每首歌最多保留两个完全相同的几何片段；超过双指接触容量的片段不用于模式学习。

谱面来源、SHA-256 和当前划分保存在 training-v3-corpus-lock.json。语料包含先前开发已使用过的歌曲，不视为全新盲测；当前模型的训练、验证和测试集合按歌曲互斥。训练标签保留 critical、flick 方向、长条尾方向及原始路径节点。

## 模型

路径模型继续使用训练集标准化、KMeans 几何/节奏聚类、跨歌曲 medoid 代表、随机森林条件选择和学习到的转移概率。比较 192 与 256 个候选簇，剔除不满足至少 20 个训练片段、至少 3 首歌曲支持的簇；只根据验证子集选择模型，再评估完整验证/测试集。镜像是同一模式的方向变换，不重复计入模式总数。

新增两个节奏条件随机森林：单键的 tap/flick 方向与 critical 组合，以及长条尾部方向与 critical 组合。输入为起音间隔、节拍相位、局部密度、同时音符数、时长和占用；不将目标键型、critical 或几何作为输入。评估未参与训练歌曲的概率损失，并与训练集类别频率基线比较。

运行时以 75% 学习后验与 25% 原声学模型提案混合，对真实训练过的标签组合采样。种子由输入起音时间确定，相同输入可复现。Trace 保持声学模型原提案；起音时间、对象数和预测长条时长保持不变。后续双指/释放约束仍可能修复长条和改变几何。

这是基于谱面节奏上下文的机器学习，不是新增音频重音的端到端监督。没有对应音频训练，不能声称 critical 一定匹配歌曲中的听觉重音，也不能仅凭模式数量证明手感足够丰富。

独立长条模型从 46,730 条训练长条学习 64 个受支持路径簇，每类保留来自不同歌曲的三个代表。以长条时长、节奏和占用学习路径类别后验，再固定种子采样。完整源路径按六列半场整体缩放/镜像，避免逐节点截断把变宽或折返压平。测试集概率损失 3.043，训练频率基线 3.332。该模型在段落模式之后应用，因此短片段中缺少兼容长条模板时仍有独立路径指导。

## 验收与复现

完整指标在 training-v3-report.json；真实音频前后对照在本地 artifacts/rich-pipeline-report.json。比较相同 NS 对象提案、起音和时长，检查实际导出的单键 flick、长条尾 flick、critical、控制点、折返和变宽，并核验实际 SUS。保守双指投影可能减少原始模板的复杂度。

两个真实音频片段的最终 SUS 对照合计：单键 flick 3 → 32；critical 对象 0 → 35；尾部 flick 0 → 5；带内部控制点的长条 15 → 43；折返 17 → 72。变宽长条 7 → 4，没有改善；不能将控制点和折返增加表述为所有形状维度均改善。隐藏控制点不是新增听觉判定。

旧/新对照使用同一 NS 提案：旧段落库与新完整生成策略比较。第一段为 60 秒，尾段不足请求长度时自动截取可用音频。最终谱面均通过 SUS 核验和社区版真实 JSON 读取。没有开展盲测手感评价。

用 tools/train_rich_patterns.py 和 tools/train_slide_paths.py 从 backend/diagnostics/pjsk_patterns_v3/corpus/ 下的分割文件训练，再用 tools/activate_rich_models.py 校验并启用，tools/export_rich_mobile.py 导出便携森林/路径，tools/prepare_mobile_models.py 更新 DSP 和锁文件。首次生成便携模型仍需运行六阶段 ONNX 导出脚本。训练语料与环境不随源码上传，须保存独立语料备份。

Windows 与 Android 使用相同的键型/重音模型和路径库。Android 尚无真机验收；文件夹输出和新版模型缓存更新目前完成源码与构建验证，实际文件提供器的行为还需手机测试。
